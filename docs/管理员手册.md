# 管理员手册

> 面向"要在自己的服务器上运营这套战令"的人。需求文档 §15 要求的「管理员 GUI 操作手册」就是本文，
> §9 的九类可编辑项与数据维护都在这里逐条说明。

---

## 1. 打开管理面板

```
/battlepass admin        # 需要 OP（原版权限等级 2 / GAMEMASTERS）
```

玩家侧打开战令界面则是 **按 `B` 键** 或输入 `/battlepass`（`B` 可在按键设置里改）。
管理面板**故意不做快捷键**：它是高权限界面，只保留需要主动输入的指令入口。

> **界面会跟随你的 GUI 缩放/窗口尺寸自动重排**：Minecraft 的界面坐标是按"GUI 缩放"换算过的
> （例如 1920×1080 屏幕、缩放 4 → 实际只有 480×270），面板会把宽高、每页行数、按钮位置
> 都按当前可用区域重新计算；窗口一改大小、缩放一改，重开后立刻生效。
> 如果你觉得内容太挤，把 GUI 缩放调小（选项 → 视频设置 → 界面尺寸）就能看到更多行。

- 权限在**服务端**校验两次：命令处一次、收到面板数据包时再一次。客户端界面是否打开过完全不影响判定（§9）。
- 非 OP 执行只会收到"需要管理员权限"，没有任何数据泄露。
- 面板**不暂停游戏**，可以边看边改。

## 2. 面板结构

### 2.1 九类设置（顶部页签，§9）

| 页签 | 内容 | 可在面板里直接改 |
|---|---|---|
| 赛季 | 赛季 ID、主题名、开关、时长、等级上限、分支解锁等级 | 开关/上限/解锁等级/时长 |
| 防肝 | 每日经验上限、每日刷新时刻、重 roll 上限、长夜开关与起止、长夜倍率、经验曲线、每级星币、豁免卡上限、devMode | 全部 |
| 任务 | 任务池条目数 + 配置文件路径 | 改文件（1 秒内自动热重载） |
| 奖励 | 已配置奖励的等级数 + 等级上限 | 改文件 |
| 商店 | 商品数 | 改文件 |
| 里程碑 | 条目数 | 改文件 |
| 事件 | 事件种类数 | 改文件 + 「开事件」手动开一场 |
| 口令 | 口令条目数 | 改文件 |
| 称号/彩蛋 | 彩蛋条目数、在线人数 | 改文件 |

> **为什么内容型清单要改文件**：50 条任务、30 级奖励、商店商品、彩蛋、口令、事件、里程碑
> 都是嵌套结构的大块内容，用游戏内文本框编辑等于做一个残缺的 JSON 编辑器，
> 既不好用也容易改坏。面板对它们给出**文件绝对路径**并支持一键导出/导入，
> 用任意编辑器改完，模组 **1 秒内自动热重载**（§2、§9 的热重载要求由所有管理器满足）。
> 这条取舍登记在 `需求偏差记录.md`。

### 2.2 数值型参数的改法（「取值」框）

在**取值**框里填 `字段=值`，多项用英文逗号分隔，然后点「应用取值（字段=值）」：

```
dailyXpCap=800, dailyRefreshTime=05:30, enabled=true
maxLevel=40, branchUnlockLevel=12
xpPerLevelBase=60, xpPerLevelStep=12
longNight.enabled=true, longNight.start=23:30, longNight.end=06:00, longNight.xpMultiplier=0.5
```

支持的字段名：`enabled`、`dailyXpCap`、`dailyRefreshTime`、`maxLevel`、`branchUnlockLevel`、
`xpPerLevelBase`、`xpPerLevelStep`、`longNight.enabled`、`longNight.start`、`longNight.end`、`longNight.xpMultiplier`。
**未识别的字段名不会发出任何请求**（避免拼错字段变成一次"看似成功"的无效修改）。
其余参数（`bonusTime.*`、`rankingEnabled`、`rankingTopN` 及各内容型清单）直接编辑对应配置文件，
1 秒内热重载，见 §3。

### 2.3 数据维护（底部按钮）

| 按钮 | 作用 | 输入 |
|---|---|---|
| **打开玩家界面** | 一键切到玩家视角（想直接看战令本身长什么样时用） | — |
| **加经验** | 像做任务一样给经验（**会升级、发星币、结算等级奖励**；长夜减半与每日上限照常生效） | 目标（留空=自己）+ 取值=数量 |
| **发豁免卡** | 给豁免卡（受 §5.9 持有上限约束） | 目标（留空=自己）+ 取值=张数 |
| **重抽任务** | 立刻重抽该玩家的每日任务；**会作废他当天的任务进度**。正常路径一天只刷一次，没有这个就没法反复测任务链路 | 目标（留空=自己） |
| **重置我的进度** | 清空自己的赛季进度（等级/经验/任务/分支/豁免卡/彩蛋进度），星币、称号库与收藏册保留 | — |
| 查询 | 显示某玩家的等级/经验/星币/分支/任务/称号/彩蛋摘要 | 目标玩家 |
| 改等级 | 直接改等级（会补结算该等级的等级奖励，不补发"升级星币"） | 目标 + 取值 |
| 改经验 | 改当前等级内经验（≥0，**不触发升级**） | 目标 + 取值 |
| 改星币 | 改永久星币 | 目标 + 取值 |
| 改分支 | 改分支（HUNT / BUILD / NONE）；改完会补发新分支的等级奖励 | 目标 + 取值 |
| 热重载 | 重读全部配置（等价于手动热重载） | — |
| 导出配置 | 备份全部配置 + state.json 到 `data/haojing_battlepass/backup/<时间戳>/` | — |
| 导入配置 | 从备份目录恢复并热重载（只接受**目录名**，不接受路径） | 取值 = 目录名 |
| 重置赛季 | 重新核对赛季；配合修改 `seasonId` 使用（见第 4 节） | — |
| 开事件 | 手动立刻开启一场随机事件 | 取值 = 事件 ID（如 `ev_double_xp`） |

「目标玩家」接受 **UUID**、**在线玩家名** 或**离线玩家的最后已知名字**；**留空表示操作对象是自己**（自测时最常用）。

### 2.4 面板第一行是"自诊断状态"

内容区第一行永远显示当前状态。遇到"打开里面什么都没有"时，它会直接说明是哪一种：

| 状态文字 | 含义 | 处理 |
|---|---|---|
| `状态：已收到管理数据（修订 N，M 秒前）` | 正常 | —— |
| `状态：服务端回执 —— 需要管理员权限` | 服务端拒绝了这次请求 | 用 OP 账号（原版权限等级 ≥ 2） |
| `状态：收到了数据但解析失败 N 次` | 通道通了但结构对不上（通常是两端 Mod 版本不一致） | 两端换成同一版本的 jar |
| `状态：尚未收到管理数据（已收到 0 个通道）` | 客户端完全没收到推送 | 看**服务端日志**有没有 `首次同步通道 admin`，再看**客户端日志**有没有 `首次收到通道 admin` |

### 2.5 管理员自测战令的推荐流程

1. `/battlepass admin` → 点**「重置我的进度」**，回到干净状态。
2. 点**「重抽任务」**（目标留空=自己）→ 立刻拿到今天的三个任务。
3. 打开玩家界面（`B` 键、`/battlepass`，或面板里的**「打开玩家界面」**），做任务、看进度。
4. 在「每日」页点**领取** → 观察经验条、星币、升级提示。
5. 嫌升级慢就点**「加经验」**（取值填 `500`）→ 会升级并结算等级奖励与星币。
6. 到 10 级会弹分支选择窗；选定后本赛季锁定。
7. 用**「发豁免卡」**验证豁免卡链路、用**「开事件」**（取值 `ev_double_xp`）验证随机事件。

## 3. 配置文件速查

所有文件都在 `config/haojing_battlepass/`。**改完不用重启**（1 秒内热重载）；
**写错的条目会被丢弃并打 WARN**，不会让整份配置失效。

| 文件 | 关键字段 | 默认值 |
|---|---|---|
| `season.json` | `seasonId` `themeName` `enabled` `cycleMode` `autoRollover` `durationDays` `seasonStartDate` `rolloverNoticeDays` `maxLevel` `branchUnlockLevel` `dailyRefreshTime` `dailyXpCap` `dailyRerollLimit` `xpPerLevelBase` `xpPerLevelStep` `starCoinPerLevel` `exemptCardMax` `devMode` `commandWhitelist` `longNight{enabled,start,end,xpMultiplier,fatigue*…}` `bonusTime{enabled,start,end,xpMultiplier}` `rankingEnabled` `rankingTopN` | 见文件内注释；S1 / 自然月 / 自动轮换 / 30 级 / 10 级解锁 / 06:00 刷新 / 上限 500 / 曲线 50+10；`bonusTime` 默认关闭（19:00~22:00、×2.0）；排行榜默认开启、Top 10；线上旧配置默认固定时长、不自动轮换（`cycleMode=fixed`、`autoRollover=false`、`seasonStartDate` 为空） |
| `daily_tasks.json` | `groups{explore,build,general}` 三组日常任务、`weeklyCount`、`weekly` 每周任务、`seasonal` 赛季挑战 | 50 条内置默认任务：日常 38（explore 14 / build 12 / general 12）+ 每周 6 + 赛季挑战 6；`weeklyCount=3` |
| `settlement.json` | `enabled` 总开关、`tiers[]`（`minLevel` `maxLevel` `rewards[]`） | 7 档等级区间结算奖励（1~4 / 5~9 / 10~14 / 15~19 / 20~24 / 25~29 / 30），赛季轮换时按旧赛季最终等级命中首个匹配档一次性发放；详见 §5.4 |
| `rewards.json` | `levels[]`：每条含 `level` `enabled` `common[]` `hunt[]` `build[]` | ~11 个等级有奖励 |
| `shop.json` | `items[]`：`id` `nameKey` `price` `limitPerPlayer` `enabled` `reward` | 7 件（3 称号 / 1 豁免卡 / 3 纹饰图案） |
| `eggs.json` | `eggs[]`（13 条，含 `condition.type` 与各自参数）+ `light{}`（聊天关键词 / 生日 / 节日） | §6 的 10 条量化定义 + 3 条轻量 |
| `codes.json` | `codes[]`：`code` `startDate` `endDate` `reward(s)` `broadcast` | 3 条示例口令 |
| `events.json` | `enabled` `checkIntervalMinutes` `rollChance` `minIntervalMinutes` `spawnMaxLightLevel` `spawnRadius` `spawnMaxAttempts` `spawnVerticalRange` + `events[]`（`type` `durationMinutes` `weight` `participation` `effects[]` `rewards[]`） | 5 分钟判定 / 8% / 最小 90 分钟 / **9 种事件**（怪物潮、天降补给、双倍经验、陨石雨、商队集结 + 2026-10 新增：掠夺者入侵、丰收庆典、钓鱼大赛、挖矿热潮）；刷怪亮度 ≤7、半径 8、每只怪找 12 个候选点、垂直高差 ≤10 |
| `milestones.json` | `milestones[]`：`metric` `scope`(TOTAL/PER_CAPITA) `threshold` `recipients`(ALL/PARTICIPANTS) `rewards[]` | 10 条 |
| `checkin.json` | `enabled` `cycleDays` `dailyRewards[][]`（第 1~cycleDays 档，按连击天数循环）`streakMilestones[]`（`streak` 连续天数 + `rewards[]`，达到一次性发放、只发一次） | 开启 / 7 天循环 / 7 档每日奖励 + 7、14、30 天里程碑；断签后连击重新累计，赛季轮换后连击清零（见 §5.2） |

奖励的写法（六类）：

```json
{ "type": "STAR_COIN", "amount": 100 }
{ "type": "BATTLEPASS_XP", "amount": 200 }
{ "type": "EXEMPT_CARD", "amount": 1 }
{ "type": "TITLE", "titleId": "haojing_scout" }
{ "type": "ITEM", "itemId": "minecraft:golden_apple", "amount": 3 }
{ "type": "COMMAND", "command": "give @s minecraft:diamond 1" }
```

- `COMMAND` **必须命中** `season.json` 的 `commandWhitelist`（默认 `give/title/tellraw/playsound/particle/effect/xp/summon`）；
  不在白名单里的命令会被拒绝并打 WARN（§9）。**不要把 `op`、`kill`、`fill` 之类加进白名单**，除非你清楚后果。
- 物品奖励需要玩家**在线**才能塞进背包；离线玩家只收得到数据类奖励（星币/称号/豁免卡/经验）。商店遇到这种情况会自动退款。
- 物品 ID 必须是**实际存在的**（写错会被丢弃并打 WARN，不会静默发空气）。

## 4. 推进赛季（重要）

赛季滚动的判据是 **"玩家存档里的 `seasonId` 与配置里的 `seasonId` 不一致"**。推进分两种方式：

### 4.0 方式一：系统自动轮换（推荐，2026-10 新增）

`season.json` 里 `autoRollover` 为 `true` 时，赛季到期由系统自动完成归档与重置，无需管理员改 `seasonId`：

1. 到期日（自然月为每月 1 号；固定时长为开始日 + `durationDays`）首轮维护检查即触发。
2. 系统把 `seasonId` 按规则递增（`S1 → S2 → S3`；非 `S+数字` 的 ID 会追加 `-yyyy-MM` 后缀避免归档串档），更新开始日期，**落盘成功后**才开始归档重置；落盘失败则本轮作废、内存回滚，下一轮重试，不会出现"配置没写进磁盘却清了档"。
3. 归档 → `data/history/season_<旧ID>.json`；重置等级/经验/任务/分支/豁免卡/彩蛋进度；保留星币、称号库、收藏册、口令记录、生日、商店购买记录；全服结算公告（滚动瞬间无人在线则留到下一名玩家上线时播）。
4. **自动轮换只清档与轮换赛季 ID，不会自动更换任务池、奖励表、主题名（`themeName`）** —— 这些仍需管理员在赛季开始前手动换配置（见 §4.2）。

### 4.1 方式二：管理员手动推进

`autoRollover` 为 `false`（旧默认口径）时：

1. 先**导出配置**备份。
2. 编辑 `season.json`，把 `seasonId` 从 `S1` 改成 `S2`（`themeName` 顺便改成新赛季名，
   `seasonStartDate` 同步更新为本季开始日期，继续启用到期提醒）。
3. 等 1 秒（热重载）后点「重置赛季」，或直接等下一次自动核对。
4. 发生的事与自动轮换相同：归档、重置、永久数据保留、全服结算公告。

### 4.2 赛季周期与日程字段

| 字段 | 含义 | 默认 |
|---|---|---|
| `cycleMode` | 周期模式：`"natural"` 自然月（每月 1 号 0 点切换，28/30/31 天跟随日历）；`"fixed"` 固定时长（持续 `durationDays` 天，历史兼容口径） | `fixed` |
| `autoRollover` | 到期后是否由系统自动归档并开启新赛季；`false` 时只做倒计时与提醒，由管理员按 §4.1 手动推进 | `false` |
| `seasonStartDate` | 赛季开始日期（`yyyy-MM-dd`）。**留空 = 关闭**到期提醒、首页倒计时与自动轮换 | 空 |
| `durationDays` | 固定时长模式的赛季天数；自然月模式下不参与结束日计算 | 30 |
| `rolloverNoticeDays` | 结束前多少天开始全服提醒（0 = 只在到期当天） | 3 |

行为：
- 配置了 `seasonStartDate` 后，进入提醒窗口（结束前 `rolloverNoticeDays` 天，含到期日）每天
  **北京时间业务日首轮维护**播报一次；已到期且赛季未推进时同样每天一次，直到 `seasonId` 被推进。
  自动轮换开启时，提醒文案为"系统将在下一轮检查时自动开启新赛季"；关闭时提示管理员手动推进。
- 同一业务日只播一次、跨重启不重复（记录在 `ServerState.lastSeasonNoticeDate`）。
- 玩家战令首页显示"本赛季剩余 N 天 / 今天到期 / 已到期"；管理员面板概览同样显示，并标注
  自动轮换开关与周期模式。
- 提醒播报前要求**至少有 1 名玩家在线**（没人看的公告不播，留到有人的时候）。
- 自然月模式下，若服务器宕机几天才开机（例如 12-03 才启动而 12-01 已到期），新赛季开始日补回
  本月 1 号（12-01），不截短当月；固定时长模式则沿旧开始日向后推 `durationDays` 天，节奏连续。
- `season.json` 首次缺失时自动从内置模板 `default_season.json` 落地（带完整中文说明）。

### 4.3 2026-11-01 新赛季上线前的配置核对

11 月 1 日开启新赛季、之后每月一个赛季，部署服在上线前确认 `season.json` 三项（内置模板只在
**首次启动**落地，不会覆盖线上已有配置）：

- `cycleMode`: `"natural"`
- `autoRollover`: `true`
- `seasonStartDate`: 本赛季开始日期；当前赛季为 2026-10 月时填 `"2026-10-01"`，
  系统将在 2026-11-01 自动轮换到 S2；11 月赛季开始后系统自动把日期更新为 `2026-11-01`，
  之后每月 1 号自动滚动，无需再手动改日期。

上线前手动更换：新赛季主题名 `themeName`、每日/每周任务池、等级奖励表、商店与称号配置
（自动轮换不会动这些内容）。

## 5. 长夜与节假日

- 长夜参数：`season.json` 的 `longNight`，或面板「防肝」页用 `longNight.*` 字段改。
  长夜期间经验 ×`xpMultiplier`（默认 0.5），**白名单管理员豁免**（`longNight.adminWhitelist` 填 UUID）。
- 节日问候与节日口令都能配 `MM-dd` 时间段（**支持跨年**，如 `12-30 ~ 01-02`）；
  留空表示不限。同一个节日/口令同一天只触发一次。
- 聊天关键词（`eggs.json` → `light.chatKeywords`）带冷却，避免刷屏。

### 5.1 经验加成时段（全员福利，默认关闭）

- 配置在 `season.json` 的 `bonusTime` 节点：`enabled`、`start`、`end`（`HH:mm`，支持跨零点）、`xpMultiplier`。
- 时段内全员战令经验 ×`xpMultiplier`（默认 2.0）；倍率与长夜、随机事件**三者相乘**（例如长夜 0.5 × 加成 2.0 = 1.0，互不抵消）。
- 与长夜的区别：加成是**正向福利**，不挂疲劳/减速等负面效果，不做管理员白名单豁免，也不弹标题预告或开始/结束广播；开启后首页显示当前倍率与剩余分钟。
- `enabled=false`（默认）时该节点不产生任何行为；起止时间非法会回退到 19:00 / 22:00，倍率夹紧在 0.0~10.0。

### 5.2 每日签到与连续登录奖励

- 配置文件 `checkin.json`（首次启动从内置模板落地，热重载；也可在管理面板的配置文件清单里直接编辑保存）。
- 玩家在战令**首页主动点「签到」**领取，不进服自动签到；业务日边界与每日任务一致（`dailyRefreshTime`，默认 06:00）。
- `dailyRewards`：按连续登录天数取档，第 1~`cycleDays` 天循环（第 8 天回到第 1 档）；`streakMilestones`：达到固定连续天数一次性发放额外奖励，**只发一次**，断签后连击重新累计。
- 断签判定：上次签到业务日不是昨天 → 连击归 1；是昨天 → 连击 +1。
- **连击与本赛季累计次数随赛季轮换清零**（存赛季数据）；星币、称号、收藏册等永久数据不受影响。里程碑奖励不建议配 `TITLE` 类型，避免引用未注册称号导致悬空。

### 5.3 赛季排行榜

- 开关 `rankingEnabled`（默认 `true`）、榜单长度 `rankingTopN`（默认 10，夹紧 1~100），都在 `season.json`。
- 服务端每 60 秒重建一次全服排名：排序口径为等级降序 → 经验降序 → 玩家名升序 → UUID 升序兜底；**离线玩家同样参与排名**（读存档聚合）。
- 客户端「排行」页签只下发 Top N 条目（名字/等级/经验/名次/是否本人），**不下发 UUID 与全量列表**；本人即使没进 Top N，也会显示全服真实名次。
- 关闭 `rankingEnabled` 后该页签显示"排行榜当前未开启"，不下发参与人数与条目。

### 5.4 赛季挑战与赛季结算奖励（2026-10 新增）

**赛季挑战（`daily_tasks.json` 的 `seasonal` 段）**

- 贯穿整赛季的长线个人目标，与每日任务、每周挑战并列第三条任务线；赛季开始时一次性全量分配，**不随每日/每周刷新，不可 reroll，不占每日选组流程，也不能用豁免跳过卡**。
- 进度在赛季内累计，**轮换时随赛季清零**，新赛季重新分配；完成后由服务端维护循环自动领取奖励（与每日选中组、每周全部任务同一自动领取范式），客户端「赛季」页签只读展示，没有领取按钮。
- 它和全服里程碑的区别：里程碑是**全服累计、全员达标共享**；赛季挑战是**个人目标、独立进度、独立奖励**，可在 `seasonal` 段照日常任务的写法配置 `action` / `target` / `xp` / `starCoin` / `filter`。

**赛季结算奖励（`settlement.json`）**

- 配置文件 `settlement.json`（首次启动从内置模板落地，热重载；也可在管理面板配置文件清单里直接编辑保存）。
- 赛季轮换时，服务端**先读玩家旧赛季最终等级**、命中 `tiers` 中首个匹配档位发奖，**然后才清空赛季数据**；开关 `enabled=false` 时轮换照常进行，只是不发任何结算奖励。
- 同一旧赛季只结算一次：已重置玩家的 `seasonId` 已等于新赛季 ID，下一轮核对时直接跳过，不会重复发奖（幂等，无需人工干预）。
- 奖励类型仅限既有六类（`STAR_COIN` / `BATTLEPASS_XP` / `EXEMPT_CARD` / `ITEM` / `COMMAND` / `TITLE`），**只做数值与装饰，不提供属性、buff 或生存增益**；等级小于 1 按 1 处理，未命中任何档位不发奖。区间重叠时以配置中先出现的档位为准，管理员需保证档位衔接。

## 6. 常见故障排查

| 现象 | 先看什么 |
|---|---|
| 玩家进服被踢，提示需要客户端 Mod | 正常拦截（§2）。本地测试可把 `devMode` 设 true；否则让玩家装客户端 jar |
| 玩家进服后界面一直"等待服务端数据" | 服务端日志里搜 `已同步通道`；确认两端协议版本一致（客户端日志会打印服务端拒绝原因） |
| 某个任务/彩蛋/商品不生效 | 搜日志里的 WARN：非法条目会被**丢弃并说明原因**（缺字段、ID 不存在、类型不识别…） |
| 改了配置没生效 | 面板点「热重载」，或确认文件确实写进去了（热重载按修改时间检测，1 秒一次） |
| 掉落/奖励没发出去 | 搜 `奖励` 与 `退款`：离线发物品会 WARN；商店失败会**退款** |
| 赛季没滚动 | 确认 `seasonId` 真的改了；再点「重置赛季」；日志里有 `赛季滚动完成` / `赛季 ID 已确认` |
| 想确认没有卡服 | 看 `长夜状态=` 定时日志与 `数据写入线程` / `里程碑计数器落盘线程` 的日志；详见《验收用例与性能说明》 |
