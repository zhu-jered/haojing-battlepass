# 管理员手册

> 面向"要在自己的服务器上运营这套战令"的人。需求文档 §15 要求的「管理员 GUI 操作手册」就是本文，
> §9 的九类可编辑项与数据维护都在这里逐条说明。

---

## 1. 打开管理面板

```
/battlepass admin        # 需要 OP（原版权限等级 2 / GAMEMASTERS）
```

玩家侧打开战令界面则是 **按 `B` 键** 或输入 `/battlepass`（`B` 可在按键设置里改）。
管理面板**故意不做快捷键**：它是高权限界面，只保留需要主动输入的指令入口。

> **界面会跟随你的 GUI 缩放/窗口尺寸自动重排**：Minecraft 的界面坐标是按"GUI 缩放"换算过的
> （例如 1920×1080 屏幕、缩放 4 → 实际只有 480×270），面板会把宽高、每页行数、按钮位置
> 都按当前可用区域重新计算；窗口一改大小、缩放一改，重开后立刻生效。
> 如果你觉得内容太挤，把 GUI 缩放调小（选项 → 视频设置 → 界面尺寸）就能看到更多行。

- 权限在**服务端**校验两次：命令处一次、收到面板数据包时再一次。客户端界面是否打开过完全不影响判定（§9）。
- 非 OP 执行只会收到"需要管理员权限"，没有任何数据泄露。
- 面板**不暂停游戏**，可以边看边改。

## 2. 面板结构

### 2.1 九类设置（顶部页签，§9）

| 页签 | 内容 | 可在面板里直接改 |
|---|---|---|
| 赛季 | 赛季 ID、主题名、开关、时长、等级上限、分支解锁等级 | 开关/上限/解锁等级/时长 |
| 防肝 | 每日经验上限、每日刷新时刻、重 roll 上限、长夜开关与起止、长夜倍率、经验曲线、每级星币、豁免卡上限、devMode | 全部 |
| 任务 | 任务池条目数 + 配置文件路径 | 改文件（1 秒内自动热重载） |
| 奖励 | 已配置奖励的等级数 + 等级上限 | 改文件 |
| 商店 | 商品数 | 改文件 |
| 里程碑 | 条目数 | 改文件 |
| 事件 | 事件种类数 | 改文件 + 「开事件」手动开一场 |
| 口令 | 口令条目数 | 改文件 |
| 称号/彩蛋 | 彩蛋条目数、在线人数 | 改文件 |

> **为什么内容型清单要改文件**：42 条任务、30 级奖励、商店商品、彩蛋、口令、事件、里程碑
> 都是嵌套结构的大块内容，用游戏内文本框编辑等于做一个残缺的 JSON 编辑器，
> 既不好用也容易改坏。面板对它们给出**文件绝对路径**并支持一键导出/导入，
> 用任意编辑器改完，模组 **1 秒内自动热重载**（§2、§9 的热重载要求由所有管理器满足）。
> 这条取舍登记在 `需求偏差记录.md`。

### 2.2 数值型参数的改法（「取值」框）

在**取值**框里填 `字段=值`，多项用英文逗号分隔，然后点「应用取值（字段=值）」：

```
dailyXpCap=800, dailyRefreshTime=05:30, enabled=true
maxLevel=40, branchUnlockLevel=12
xpPerLevelBase=60, xpPerLevelStep=12
longNight.enabled=true, longNight.start=23:30, longNight.end=06:00, longNight.xpMultiplier=0.5
```

支持的字段名：`enabled`、`dailyXpCap`、`dailyRefreshTime`、`maxLevel`、`branchUnlockLevel`、
`xpPerLevelBase`、`xpPerLevelStep`、`longNight.enabled`、`longNight.start`、`longNight.end`、`longNight.xpMultiplier`。
**未识别的字段名不会发出任何请求**（避免拼错字段变成一次"看似成功"的无效修改）。

### 2.3 数据维护（底部按钮）

| 按钮 | 作用 | 输入 |
|---|---|---|
| **打开玩家界面** | 一键切到玩家视角（想直接看战令本身长什么样时用） | — |
| **加经验** | 像做任务一样给经验（**会升级、发星币、结算等级奖励**；长夜减半与每日上限照常生效） | 目标（留空=自己）+ 取值=数量 |
| **发豁免卡** | 给豁免卡（受 §5.9 持有上限约束） | 目标（留空=自己）+ 取值=张数 |
| **重抽任务** | 立刻重抽该玩家的每日任务；**会作废他当天的任务进度**。正常路径一天只刷一次，没有这个就没法反复测任务链路 | 目标（留空=自己） |
| **重置我的进度** | 清空自己的赛季进度（等级/经验/任务/分支/豁免卡/彩蛋进度），星币、称号库与收藏册保留 | — |
| 查询 | 显示某玩家的等级/经验/星币/分支/任务/称号/彩蛋摘要 | 目标玩家 |
| 改等级 | 直接改等级（会补结算该等级的等级奖励，不补发"升级星币"） | 目标 + 取值 |
| 改经验 | 改当前等级内经验（≥0，**不触发升级**） | 目标 + 取值 |
| 改星币 | 改永久星币 | 目标 + 取值 |
| 改分支 | 改分支（HUNT / BUILD / NONE）；改完会补发新分支的等级奖励 | 目标 + 取值 |
| 热重载 | 重读全部 8 份配置（等价于手动热重载） | — |
| 导出配置 | 备份 8 份配置 + state.json 到 `data/haojing_battlepass/backup/<时间戳>/` | — |
| 导入配置 | 从备份目录恢复并热重载（只接受**目录名**，不接受路径） | 取值 = 目录名 |
| 重置赛季 | 重新核对赛季；配合修改 `seasonId` 使用（见第 4 节） | — |
| 开事件 | 手动立刻开启一场随机事件 | 取值 = 事件 ID（如 `ev_double_xp`） |

「目标玩家」接受 **UUID**、**在线玩家名** 或**离线玩家的最后已知名字**；**留空表示操作对象是自己**（自测时最常用）。

### 2.4 面板第一行是"自诊断状态"

内容区第一行永远显示当前状态。遇到"打开里面什么都没有"时，它会直接说明是哪一种：

| 状态文字 | 含义 | 处理 |
|---|---|---|
| `状态：已收到管理数据（修订 N，M 秒前）` | 正常 | —— |
| `状态：服务端回执 —— 需要管理员权限` | 服务端拒绝了这次请求 | 用 OP 账号（原版权限等级 ≥ 2） |
| `状态：收到了数据但解析失败 N 次` | 通道通了但结构对不上（通常是两端 Mod 版本不一致） | 两端换成同一版本的 jar |
| `状态：尚未收到管理数据（已收到 0 个通道）` | 客户端完全没收到推送 | 看**服务端日志**有没有 `首次同步通道 admin`，再看**客户端日志**有没有 `首次收到通道 admin` |

### 2.5 管理员自测战令的推荐流程

1. `/battlepass admin` → 点**「重置我的进度」**，回到干净状态。
2. 点**「重抽任务」**（目标留空=自己）→ 立刻拿到今天的三个任务。
3. 打开玩家界面（`B` 键、`/battlepass`，或面板里的**「打开玩家界面」**），做任务、看进度。
4. 在「每日」页点**领取** → 观察经验条、星币、升级提示。
5. 嫌升级慢就点**「加经验」**（取值填 `500`）→ 会升级并结算等级奖励与星币。
6. 到 10 级会弹分支选择窗；选定后本赛季锁定。
7. 用**「发豁免卡」**验证豁免卡链路、用**「开事件」**（取值 `ev_double_xp`）验证随机事件。

## 3. 八份配置文件速查

所有文件都在 `config/haojing_battlepass/`。**改完不用重启**（1 秒内热重载）；
**写错的条目会被丢弃并打 WARN**，不会让整份配置失效。

| 文件 | 关键字段 | 默认值 |
|---|---|---|
| `season.json` | `seasonId` `themeName` `enabled` `durationDays` `maxLevel` `branchUnlockLevel` `dailyRefreshTime` `dailyXpCap` `dailyRerollLimit` `xpPerLevelBase` `xpPerLevelStep` `starCoinPerLevel` `exemptCardMax` `devMode` `commandWhitelist` `longNight{enabled,start,end,xpMultiplier,fatigue*…}` | 见文件内注释；S1 / 30 天 / 30 级 / 10 级解锁 / 06:00 刷新 / 上限 500 / 曲线 50+10 |
| `daily_tasks.json` | `groups{explore,build,general}` 各 12 条、`weeklyCount`、`weekly` 6 条 | 42 条内置默认任务 |
| `rewards.json` | `levels[]`：每条含 `level` `enabled` `common[]` `hunt[]` `build[]` | ~11 个等级有奖励 |
| `shop.json` | `items[]`：`id` `nameKey` `price` `limitPerPlayer` `enabled` `reward` | 7 件（3 称号 / 1 豁免卡 / 3 纹饰图案） |
| `eggs.json` | `eggs[]`（13 条，含 `condition.type` 与各自参数）+ `light{}`（聊天关键词 / 生日 / 节日） | §6 的 10 条量化定义 + 3 条轻量 |
| `codes.json` | `codes[]`：`code` `startDate` `endDate` `reward(s)` `broadcast` | 3 条示例口令 |
| `events.json` | `enabled` `checkIntervalMinutes` `rollChance` `minIntervalMinutes` + `events[]`（`type` `durationMinutes` `weight` `participation` `effects[]` `rewards[]`） | 5 分钟判定 / 8% / 最小 90 分钟 / 5 种事件 |
| `milestones.json` | `milestones[]`：`metric` `scope`(TOTAL/PER_CAPITA) `threshold` `recipients`(ALL/PARTICIPANTS) `rewards[]` | 10 条 |

奖励的写法（六类）：

```json
{ "type": "STAR_COIN", "amount": 100 }
{ "type": "BATTLEPASS_XP", "amount": 200 }
{ "type": "EXEMPT_CARD", "amount": 1 }
{ "type": "TITLE", "titleId": "haojing_scout" }
{ "type": "ITEM", "itemId": "minecraft:golden_apple", "amount": 3 }
{ "type": "COMMAND", "command": "give @s minecraft:diamond 1" }
```

- `COMMAND` **必须命中** `season.json` 的 `commandWhitelist`（默认 `give/title/tellraw/playsound/particle/effect/xp/summon`）；
  不在白名单里的命令会被拒绝并打 WARN（§9）。**不要把 `op`、`kill`、`fill` 之类加进白名单**，除非你清楚后果。
- 物品奖励需要玩家**在线**才能塞进背包；离线玩家只收得到数据类奖励（星币/称号/豁免卡/经验）。商店遇到这种情况会自动退款。
- 物品 ID 必须是**实际存在的**（写错会被丢弃并打 WARN，不会静默发空气）。

## 4. 推进赛季（重要）

赛季滚动的判据是 **"玩家存档里的 `seasonId` 与配置里的 `seasonId` 不一致"**：

1. 先**导出配置**备份。
2. 编辑 `season.json`，把 `seasonId` 从 `S1` 改成 `S2`（`themeName` 顺便改成新赛季名）。
3. 等 1 秒（热重载）后点「重置赛季」，或直接等下一次自动核对。
4. 发生的事：**归档** → `data/history/season_S1.json`（同赛季多次滚动会合并去重）；
   **重置** 等级/经验/任务/分支/豁免卡/彩蛋进度；**保留** 星币、称号库、收藏册、口令记录、生日、商店购买记录。
5. 全服会收到一条结算公告（若滚动的瞬间没有人在线，公告会留到下一名玩家上线时播）。

## 5. 长夜与节假日

- 长夜参数：`season.json` 的 `longNight`，或面板「防肝」页用 `longNight.*` 字段改。
  长夜期间经验 ×`xpMultiplier`（默认 0.5），**白名单管理员豁免**（`longNight.adminWhitelist` 填 UUID）。
- 节日问候与节日口令都能配 `MM-dd` 时间段（**支持跨年**，如 `12-30 ~ 01-02`）；
  留空表示不限。同一个节日/口令同一天只触发一次。
- 聊天关键词（`eggs.json` → `light.chatKeywords`）带冷却，避免刷屏。

## 6. 常见故障排查

| 现象 | 先看什么 |
|---|---|
| 玩家进服被踢，提示需要客户端 Mod | 正常拦截（§2）。本地测试可把 `devMode` 设 true；否则让玩家装客户端 jar |
| 玩家进服后界面一直"等待服务端数据" | 服务端日志里搜 `已同步通道`；确认两端协议版本一致（客户端日志会打印服务端拒绝原因） |
| 某个任务/彩蛋/商品不生效 | 搜日志里的 WARN：非法条目会被**丢弃并说明原因**（缺字段、ID 不存在、类型不识别…） |
| 改了配置没生效 | 面板点「热重载」，或确认文件确实写进去了（热重载按修改时间检测，1 秒一次） |
| 掉落/奖励没发出去 | 搜 `奖励` 与 `退款`：离线发物品会 WARN；商店失败会**退款** |
| 赛季没滚动 | 确认 `seasonId` 真的改了；再点「重置赛季」；日志里有 `赛季滚动完成` / `赛季 ID 已确认` |
| 想确认没有卡服 | 看 `长夜状态=` 定时日志与 `数据写入线程` / `里程碑计数器落盘线程` 的日志；详见《验收用例与性能说明》 |
